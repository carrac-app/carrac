What it is
BYOAI — your model, your key

A data layer for any AI client.

Carrac implements the Model Context Protocol — a standard that lets AI assistants call structured tools. When you connect Claude Desktop, Claude Code, Cursor, or any other MCP client, it gains access to Carrac's full market-data and analysis surface through your own model. The AI computation runs on your side.

  • Connect with Claude Desktop, Claude Code, Cursor, or any MCP client
  • Use your own model and API key — Carrac never processes your queries
  • Structured tools, resources, and prompt workflows — not a chat wrapper
  • Every tool is available to your own model through one MCP endpoint

How to connect

Any MCP client. Your own key.

Carrac's MCP server works with any client that supports the Model Context Protocol. Tested clients include Claude Desktop, Claude Code, and Cursor — any other MCP-compatible agent or IDE extension should connect the same way.

Configuration details and the full connection guide are in the Carrac guide. MCP requires a Carrac account and an API key.

  • Claude Desktop — add Carrac as an MCP server in your config
  • Claude Code — wire Carrac's MCP endpoint into your project
  • Cursor — add as a custom MCP server in Cursor settings
  • Any MCP client — standard protocol, any compatible client
Resources & prompts

Grounded context. Structured workflows.

MCP Resources give your AI client structured reference material it can read before calling tools — reducing hallucination and keeping responses grounded in Carrac's actual data model.

  • Indicator glossary — definitions for every indicator and quant term Carrac uses
  • Anti-hallucination grounding rules — hard constraints on what the model should and should not assert about market data
  • Live macro facts — current ground-truth values (rates, yields, key levels) updated regularly so the model doesn't rely on stale training memory

MCP Prompts are structured, reusable workflows that surface in your client's prompt picker. Each guides the AI through a specific analytical task using Carrac data.

  • validate-trade — systematic checklist to evaluate a trade idea against current market regime, correlations, and indicator state
  • design-trade — structure a trade from thesis to entry conditions, risk parameters, and scenario branches
  • analyze-asset — full cross-layer analysis of a single asset: price structure, quant signals, regime context, and sentiment
Data is information to evaluate — not a buy or sell signal. Your analysis stays yours. Carrac never sees it.
Data ownership & posture

Your AI. Your conclusions.

Because Carrac's MCP server is a data provider — not an inference provider — the model that interprets Carrac's data runs entirely on your side, under your API key. Carrac does not log your prompts, does not see your queries, and does not influence your model's outputs.

The market regime surface, the quant signals, and the indicator data are all information for you to evaluate. Carrac presents data; it never says buy, sell, or what position to take.

  • Your model, your API key — inference runs on your side
  • Carrac does not process or log your MCP queries
  • Data is auditable — every source is named
  • Non-advice posture: information to evaluate, never a recommendation
